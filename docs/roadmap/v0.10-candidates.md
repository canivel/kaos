### 1. `core-storage-hardening` — score 9.5 (M)

Reproduced P0s in the VFS core:

- **`write()` version collision** — `core.py:291-305` computes `MAX(version)` over `deleted=0` rows only, against `UNIQUE(agent_id,path,version)` spanning tombstones (`schema.py:40`). Delete-then-rewrite and restore-then-write crash with `IntegrityError`. This defeats checkpoint/time-travel — the core product premise.
- **`read()` holds an open write transaction** — `core.py:277` logs FILE_READ via an uncommitted INSERT (`events.py:36-40`); every reader blocks every writer db-wide. The parked storage-scale bench is unmeasurable until this is fixed.
- **Helper objects pin the init thread's connection** — BlobStore/EventJournal/CheckpointManager; make connection-per-call.
- **`query()` read-only enforcement is a 6-keyword prefix blacklist** (`core.py:633-645`) that passes `REPLACE`/`WITH..DELETE`/`PRAGMA`/`ATTACH`/`VACUUM INTO` on the full-privilege connection — reachable by agents via MCP `agent_query`. Enforce at the SQLite layer (mode=ro connection or authorizer). Also parameterize the f-string SQL in `mh_next_iteration`.
- **SharedLog position race** — read-then-insert on UNIQUE position; make it an atomic `INSERT..SELECT`.
- **Blob GC** — `ref_count` is write-only today; DB grows forever. Mark-and-sweep `kaos gc` with checkpoints as GC roots.

Gates: G1 red-first repro tests for all three P0s; G2 threaded stress (8 threads, 30s, zero IntegrityError, readers never block writers); G3 adversarial query() suite (≥12 payloads, 100% blocked at SQLite layer, zero false positives on legitimate corpus); G4 GC safety (restore every checkpoint post-GC byte-identical); G5 write() atomicity under injected fault. Risks: scope bundling (GC is splittable if it slips); WAL behavior change on win32 needs explicit testing; FILE_READ audit semantics change must be a pre-registered decision.

### 2. `eval-harness-integrity` — score 9.0 (M)

The discipline's own tooling has holes:

- **P0: `Probe.verify()` crashes on every results.json the reference probe produces** (KeyError `per_query` on completed runs; KeyError `FULL` on the shipped VOID file).
- **The blind-judge kappa is tautological** — `judge.py:91` computes `jq.correct == jq.correct`, always 1.0; the kappa VOID gate is dead code.
- **An empty kill-gate list computes ACCEPT** in `compute_verdict` — a probe that registers zero gates auto-passes.

Fixes: short-circuit VOID in verify(); guard compute_verdict against zero kill-gates (VOID, not ACCEPT); persist per_query per arm in results.json; extract a real independent kappa signal from SurrogateVerifier or explicitly document mechanical-label probes as kappa-exempt; unit-test that a disagreeing judge actually lowers kappa. Two judges called these "credibility-fatal to the framework's core narrative" — the narrative is the verdicts.

### 4. `storage-scale-bench` — score 8.2 (M) — **DONE (2026-06-24). Verdict: single-DB does NOT saturate; per-agent-DB sharding is REJECT-by-measurement.**

> **LANDED.** Built `demo_storage_scale_bench/` and ran 1k/10k agents + a real pragma sweep. Results (`demo_storage_scale_bench/README.md`):
> - **Cross-agent FTS5 search does not saturate:** memory_search p95 = 1.5 ms @ 1k, **9.2 ms @ 10k** — ~55× under the 500 ms sanity line. The "one big DB won't scale for shared structures" premise is **false**.
> - **The real bottleneck is write-commit contention, flat with scale** (~2 s p95 at `synchronous=FULL`, 8 threads) — writer contention, not data volume.
> - **One pragma removes it:** `synchronous=NORMAL` → vfs_write p95 1895 ms → **15 ms (~125×)**, throughput 29 → **1118 ops/s (~38×)**, zero lock errors. Made `synchronous`/`wal_autocheckpoint` configurable on `Kaos()` (default preserved at FULL/100; NORMAL recommended — author's call to flip).
> - **Decision:** per-agent-DB sharding would be a feature-losing rewrite (loses cross-agent FTS5, Hebbian associations, shared log) to solve a bottleneck a config line already solves → **REJECT-by-measurement for the throughput rationale.** `federation-pkg-layer` is storage-agnostic and proceeds unchanged on the single-DB architecture. The only remaining case for per-tenant DBs is *governance* (physical isolation / per-tenant deletion), which would be scoped on those grounds with its own gates — not performance.

The parked Step-0 bench: 1k/10k/100k agents, mixed workload from K threads + M processes; p50/p99 per-op latency, lock-error rate, DB+WAL growth, checkpoint duration. Sweep `synchronous={FULL,NORMAL}` × `wal_autocheckpoint={100,1000,4000}` — the current values (`core.py:57`) are unmeasured guesses. Folds in verified scale hotspots: checkpoint manifests stored as O(files) inline JSON (dedupe via BlobStore), `/pareto/history.jsonl` O(n²) rewrite-append. **Sequenced after Tier 0** (the reader-lock bug makes measurements meaningless). This is the sole prerequisite for un-parking the per-agent-DB / Data Vault decision.

## Tier 2 — Mechanisms (each REQUIRES its own pre-registered probe; nothing ships on this doc alone)

### 9. `federation-pkg-layer` — score 7.3 (L) — *the strategic build*

The parked `kaos pkg export/install` layer with the 2026 threat model designed in: manifest aligned with APS v0.1 (implemented natively — no apstool dependency); local Ed25519 signing default, sigstore keyless as OPTIONAL backend (mandatory Fulcio/Rekor would violate local-first); OASF capability taxonomy indexed via existing FTS5 (`kaos pkg search` by BM25); provenance block; quarantine-import (imported agents land deprecated/untrusted until locally validated). The only candidate that directly BUILDS the company-vault goal. Storage decision (single vs per-agent DB) explicitly NOT blocked: the pkg layer is storage-agnostic.

### 10. `skill-admission-gate` — score 6.7 (L)

One merged probe attacking the hole the HASP rejection exposed: executable-program skills (ASI, arXiv:2504.06821) admitted only after **counterfactual verification** (SkillGen, arXiv:2605.10999) — run identical instances with/without the skill, count repairs n01 vs regressions n10, admit only if `n01−n10 ≥ max(2, 5% of m)`. Prices in the 39/49 zero-gain prior instead of ignoring it. The admission gate is itself the missing piece that would let ANY future skill-transfer claim be settled permanently. Honest survival prior ~0.35 — and a REJECT would close the entire skills-transfer question with evidence.

### 11. `truf-probe` — score 6.7 (M)

The parked MATM-distillation, upgraded with a review finding: pre-register an additional kill arm **B0′ = random/recency exemplar sampling with zero retrieval machinery** (CBR literature: random often beats similarity retrieval for diverse contextual reasoning, arXiv:2504.06943). TRUF must beat native FTS5+plasticity AND random or `[KILL]`. Side effect: retroactively stress-tests whether native retrieval itself beats random — something KAOS has never measured. Value on every verdict branch.

### 12. `runtime-policy-taint` — score 6.0 (L) — *sequenced behind #9*

Security overlay in three SQLite-native layers: AgentSpec-style declarative policy gate between decision and tool dispatch (deny/transform/escalate, journaled); CaMeL-subset taint tracking via verbatim token overlap + FTS5 (explicitly NOT embedding attribution); origin-bounded trust for cross-agent memory. The cost/priority judge PARKed it: the channel it defends (imported agents, federated memory) sits behind the federation layer, which sits behind the storage bench. Right design, premature slot — build the policy-gate skeleton with the federation layer, not before.
