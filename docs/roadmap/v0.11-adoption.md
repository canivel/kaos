The pivotal observation: **Pi's deliberate omissions are KAOS's core features.** Pi's own
docs say: sub-agents "via tmux or extensions", sandboxing "containerize yourself", memory
"skills + AGENTS.md", orchestration is herdr's / OpenClaw's job. Pi carved out exactly the
territory KAOS occupies — and its 100k users now solve those problems with tmux panes and
markdown files.

## 2. How Pi got 100k stars (traction mechanics, not magic)

1. **Two-minute win.** One npm command → working agent. No config wizard before value.
2. **A retellable contrarian narrative with hard numbers.** "Playwright MCP costs 13.7k
   tokens for 21 tools; my 225-token README of CLI scripts beats it." Repeated HN front
   pages ("What if you don't need MCP at all?", "Ask HN: Why is Pi so good").
3. **A magic demo.** Self-extension: *ask Pi to build the feature you're missing*, reload,
   keep working. Ronacher's post ("malleable like clay") was the credibility multiplier.
4. **Unbundled architecture.** pi-ai, pi-tui, pi-agent-core each earn users standalone;
   OpenClaw adopting pi-agent-core made Pi infrastructure, not just an app.
5. **Community surface area.** A package system + registry means contributors ship value
   without touching core — 287 contributors, extensions ecosystem.
6. **Author reputation + institutional backing + daily releases.** Compounding trust.

## 3. Why KAOS has 9 stars — honest diagnosis

- **G-diag-1: Install friction.** Not on PyPI (name squatted); clone-and-uv only. Nobody
  can `uvx` it, no pinned versions, no release notes channel.
- **G-diag-2: First impression.** The repo root ships 18 `demo_*` bench directories,
  `.db` files, `*.log` files, and loose PNGs. It reads as a research workspace, not a
  product. The README leads with epistemology (falsifiable kill gates) before the reader
  has seen the product work.
- **G-diag-3: Vocabulary tax.** Neuroplasticity, Hebbian, dream cycle, ISA/ISC, GEPA,
  AAAK, meta-harness — seven proprietary terms before the first command. Pi's vocabulary:
  read, write, edit, bash.
- **G-diag-4: Monolith.** You cannot adopt the flight recorder without also getting the
  router, dream cycle, and meta-harness. There is no small piece to fall in love with.
- **G-diag-5: No ecosystem surface.** Integrations are inbound (papers implemented) rather
  than outbound (tools people already run). No plugin API, no extension registry, no way
  for a stranger to contribute a unit of value.
- **G-diag-6: Nothing rides on KAOS.** Pi is loved partly because herdr, OpenClaw, and
  extensions ride on it. Nothing external depends on KAOS yet.

What is **not** the problem: Python (uv/uvx solved Python CLI distribution), the feature
set (it's the exact set Pi's users are told to improvise), or the discipline (it's the
single most differentiated asset — "15 mechanisms evaluated, 0 shipped on hope" is an
HN-front-page story that no other framework can tell).

## 4. What one can achieve vs. the other

- **Pi** is a *daily-driver coding agent*: the loop you sit in all day. It is deliberately
  amnesiac, unaudited, unsandboxed, single-agent. Its answer to fleet questions is
  "tmux + extensions."
- **KAOS** is *fleet infrastructure*: isolation, time-travel, forensics ("which tool call
  failed, what did it cost"), compounding memory/skills across sessions, and verified
  harness evolution. It does not want to be the loop you sit in — its providers already
  wrap Claude Code / the Agent SDK.

They are complementary layers. The losing move is building "KAOS the coding agent" to
fight Pi/Claude Code head-on. The winning move is becoming **the flight recorder and
shared brain for whatever agent you already run** — including Pi.

## 5. Strategy

> **Unbundle KAOS into small, one-command pieces that attach to the agents people already
> use (Pi, Claude Code, herdr/tmux fleets), and tell the discipline story with hard
> numbers.**

Everything below serves that sentence.

### P1 — Modularize: one package, extras + plugins (target: 1 month) — gates BINDING

Pi's five focused packages are the model for *modularity*, not for *distribution count*.
Five PyPI distributions for a one-maintainer project is a version matrix, five release
pipelines, and cross-package compat debt — npm monorepo tooling makes that cheap for Pi;
Python doesn't. We get the same "small piece to fall in love with" with **one
distribution** using the Python-native pattern (pytest, Datasette, Flake8 all work this
way):

**a) One dist, tiered by extras.** `pip install kaos-harness` installs only the core:
VFS, checkpoints, event journal, blobs, memory + skills. Everything heavier is an extra
whose deps only install when asked:

| Install | Adds | Deps moved out of base |
|---|---|---|
| `kaos-harness` | flight recorder + brain (the small clean version) | base: `click`, `ulid-py`, `zstandard`, `pyyaml`, `rich` (8 → 5; `rich` stays — the CLI renders through it) |
| `kaos-harness[mcp]` | the 58-tool MCP server | `mcp` |
| `kaos-harness[router]` | GEPA router + providers | `httpx` |
| `kaos-harness[ui]` | TUI + web dashboard | `rich`, `textual` |
| `kaos-harness[eval]` | falsifiable-probe harness + experiments journal (no extra deps today — the extra exists so the surface is named and can grow) | — |
| `kaos-harness[all]` | today's full experience | everything |

CLI subcommands stay registered but fail helpfully: `kaos serve` without `[mcp]` prints
the exact install line. Import layering is enforced, not aspirational: core modules must
not import router/mcp/ui/eval at module level.

**b) Entry-point plugin API for everything third-party.** One group,
`kaos.plugins`, discovered via `importlib.metadata.entry_points()` — pluggy-style hooks
for: model providers, mh benchmarks, dream phases, MCP tool packs, and fleet adapters
(the P2 herdr/tmux/pi bridges ship as plugins, not core). Third parties publish their own
packages (`kaos-plugin-*`); *we* still publish exactly one.

**G1.1:** base install has ≤ 5 third-party deps and `import kaos` works with no extras
installed. *(Amended from ≤ 4 before implementation: `rich` is a module-level dependency
of the CLI entry point; rewriting the CLI's rendering to drop it would be churn without
adoption value. The amendment is recorded here, not hidden.)* **G1.2:** layering test — core never imports an extra's module at import time;
every extra's absence produces an actionable CLI message, not a traceback. **G1.3:** a
toy third-party plugin (provider + one MCP tool) installs from a separate wheel and is
discovered with zero kaos-harness code changes.

### P3 — Narrative & community (continuous) — gates directional

- **Tell the discipline story with Zechner-grade numbers.** Three posts, each one
  retellable fact: (1) "We evaluated 15 mechanisms and shipped 0 on hope — here are the
  locks, verdicts, and what each REJECT saved"; (2) "SQLite as agent flight recorder:
  10k agents, 9.2 ms p95 search, one file"; (3) "Your agent's memory should be
  falsifiable: the kill-gate pattern in 100 lines." Submit to HN honestly, once each.
  **G3.1:** all three published with reproducible numbers (`kaos eval verify-numerics`
  passes on each — dogfood the tool).
- **Open the contribution surface.** Entry-point-based plugin API (custom providers,
  benchmarks, dream phases, MCP tool packs); `CONTRIBUTING.md`; 10 good-first-issues;
  the AI-agent issue policy already exists — advertise it. **G3.2:** first merged PR from
  a non-author contributor.
- **Docs site parity.** canivel.github.io/kaos already exists — add versioned docs and a
  package index page as P1/P2 artifacts ship.

### Non-goals (explicit, so we don't drift)

- **No KAOS coding agent.** We wrap loops; we don't compete with them.
- **No minimalism cosplay.** Pi's 4-tool asceticism is *its* differentiator; ours is
  verified infrastructure. Unbundling ≠ feature deletion.
- **No MCP retreat.** Pi's no-MCP stance is right *for a single agent's context budget*;
  KAOS's MCP server is how host agents reach the fleet. Keep it — but publish per-tool
  token cost so the trade-off is measured, not vibes (Zechner's own standard).
- **No new mechanisms during P0–P1.** The discipline holds: distribution debt first.

## 7. Verdict framing

Run this roadmap like a probe: P0/P1 gates are binding (they measure things we fully
control — friction, packaging, hygiene); P2/P3 gates are directional and reviewed at
+60/+90 days. If G2.1–G2.3 all fail despite shipping, the "attach to existing agents"
hypothesis is REJECTED and the next candidate strategy (kaos-eval as the standalone
flagship) gets its own probe. Log outcomes in the experiments journal
(`family=adoption`) — what we tried should be queryable, same as everything else.
