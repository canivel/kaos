The differentiator

Nothing ships without a probe it could fail.

Most frameworks add mechanisms and report the demo that worked. KAOS evaluates every mechanism candidate against a pre-registered, hash-locked, falsifiable probe before shipping it — and reports the verdict either way.

01 · Pre-register

Gates before code

Kill gates are written into an ISA.lock.json and sha256-locked before any feature code exists. The harness refuses to run on an edited lock — goalpost moves are mechanically impossible.

02 · Falsify

Prove it can lose

A self-test substitutes the feature with its baseline and confirms the gate fires. A harness in which the feature can't lose is inadmissible; its later "pass" is meaningless.

03 · Report honestly

ACCEPT / REJECT / VOID

The binding verdict is committed as-is. No retune-and-rerun. REJECT and VOID are successful outcomes — they keep unproven mechanisms out of the framework.

The apparatus that has rejected eight of nine mechanism ideas is itself a shipped, tested primitive: kaos eval probe {run,verify,falsify}. KAOS is the first agent framework that ships its own kill-switch. Read the v0.9 story →
